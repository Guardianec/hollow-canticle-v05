You are continuing development of **Hollow Canticle**.

This release is:

# Hollow Canticle v0.7.0 — Living Steel & Foundations

This is a major combined release.

It combines what would otherwise have been:

- a technical/foundation patch;
- an animation overhaul;
- a combat-presentation overhaul;
- a new playable character release.

The primary goal is:

> Make Hollow Canticle feel dramatically more alive, fluid, readable, polished, and responsive without breaking multiplayer or the existing gameplay systems.

This release must improve:

1. character locomotion;
2. idle animation;
3. combat stance animation;
4. animation transitions;
5. turning behavior;
6. enemy animation identity;
7. combat VFX;
8. Shinobi playable character;
9. dungeon collision/visual consistency;
10. item-selection clarity;
11. optional tutorial;
12. graphics presets;
13. low-end optimization;
14. infrastructure for future Extreme graphics.

Do NOT turn this release into the difficulty/boss/weather overhaul.

Those belong primarily to later releases.

# 5. CURRENT ANIMATION PROBLEM

The existing animation system has improved significantly, but characters still often feel like:

> articulated figures changing poses

rather than:

> living characters moving through space.

The largest problems are:

- weak locomotion;
- insufficient body movement;
- overly static idle poses;
- limited transition animation;
- abrupt state changes;
- weak turning response;
- insufficient anticipation/recovery;
- characters sometimes appearing like statues when not attacking.

v0.7 must solve this.

---

# 6. ANIMATION SYSTEM V2

Do NOT simply add more `if state === ...` pose branches.

Create a proper layered animation-state system.

Conceptually:

```text
AnimationStateMachine

LOCOTION LAYER
    idle
    long-idle
    start-run
    run
    turn
    stop-run
    combat-forward
    combat-backward
    combat-strafe

ACTION LAYER
    attack
    parry
    perfect-parry
    dodge
    ranged
    item
    finisher
    riposte

ADDITIVE LAYER
    breathing
    head tracking
    cloth motion
    recoil
    impact
```

Exact architecture is your decision.

The important result:

different animation systems can blend together naturally.

# 7. TRANSITIONS ARE A CORE REQUIREMENT

Characters must no longer snap directly between major states.

Examples:

```text
idle
→ run-start
→ run
```

and:

```text
run
→ stop
→ idle
```

and:

```text
combat-idle
→ attack-windup
→ strike
→ recovery
→ combat-idle
```

and:

```text
parry
→ counter
```

and:

```text
parry
→ Shinobi riposte
```

Use short blending windows.

Avoid visible pose snapping.

# 8. ANIMATION BLENDING

Implement proper blend/interpolation between clips.

Do not reset every joint toward zero between actions.

An attack beginning from combat stance should inherit that stance.

A dodge beginning while running should preserve movement direction.

A character stopping should decelerate visually.

Use:

- blend-in;
- blend-out;
- transition pose;
- additive channels where useful.

# 16. LOCOMOTION V2

Movement is one of the highest-priority improvements.

The player's actual movement speed should NOT change merely because running animation looks faster.

The character should visually run at the existing gameplay speed.

---

# 17. FORWARD RUN

Create believable forward locomotion.

Requirements:

- slight forward lean;
- torso reacts to acceleration;
- head stays relatively stable;
- legs cycle naturally;
- arms balance body;
- weapon is stabilized appropriately;
- cloth trails;
- feet do not visibly slide excessively.

The reference image will demonstrate desired lean.

Do not exaggerate into sprinting.

---

# 18. MOVEMENT START

When input begins from idle:

do not instantly enter full run cycle.

Use a short acceleration animation.

Example:

```text
idle

weight shift

front foot step

body leans

full run
```

This can happen very quickly.

Controls must remain responsive.

Simulation movement begins immediately.

Animation simply represents the acceleration visually.

---

# 19. MOVEMENT STOP

When movement ends:

run cycle should not freeze instantly.

Use:

- final step;
- torso deceleration;
- slight forward momentum;
- stance recovery.

Again:

do not introduce gameplay input lag.

This is visual.

---

# 20. TURNING

Movement animations MUST understand turning.

This is explicitly required.

If player gradually changes direction:

- hips lead rotation;
- torso follows;
- shoulders lag slightly;
- legs adjust step direction;
- cape trails behind.

---

# 21. SHARP TURN

For strong direction change such as:

```text
forward
→ backward
```

use a brief pivot/plant motion.

Possible:

- plant outside foot;
- rotate hips;
- lean;
- push off.

Do not make it long enough to affect movement response.

---

# 22. CHARACTER BANKING

When running through curves:

slight body banking is desirable.

Keep subtle.

Not racing-game levels of tilt.

---

# 23. STRAFE / CLOSE COMBAT LOCOMOTION

During close combat camera:

do NOT use normal exploration run animation.

Characters should switch to combat locomotion.

Forward:

guarded advance.

Backward:

controlled backstep/backpedal.

Left/right:

combat sidestep.

Weapon remains ready.

Body faces opponent more strongly.

---

# 24. COMBAT STANCE

When an enemy is actively focused in close encounter:

character enters a ready stance.

Requirements:

- knees slightly bent;
- weapon ready;
- shoulders aligned toward threat;
- head tracks target;
- body weight balanced;
- subtle movement.

The stance should communicate:

> ready to strike, dodge or deflect.

# FINAL DESIGN DIRECTIVE

v0.7 should change one of the most important subconscious impressions players have of Hollow Canticle.

Right now a character can sometimes feel like:

> a model being moved through a game.

After this release, it should feel like:

> a person moving through a dangerous world.

When the player begins moving:

their weight shifts.

They lean forward.

Their weapon reacts.

Their cloak follows.

When they turn:

their hips, shoulders and feet respond.

When they stop:

momentum settles naturally.

When they stand still:

they breathe.

They move.

After a while they interact with their weapon.

When combat starts:

their entire posture changes.

They become ready.

When an enemy strikes:

a deflection feels violent.

A perfect deflection feels exceptional.

When guard breaks:

the whole encounter visibly changes.

And when the Shinobi lands a perfect deflection:

he should be able to explode forward,

cut through the opening,

and disappear backward into guard before the enemy can recover.

At the same time:

the dungeon must stop lying to the player about where walls exist.

The selected item must be obvious.

The tutorial must be accessible.

Low-end PCs must have a real Very Low mode.

High-end PCs should be able to select Extreme.

Do not treat these as unrelated features.

They all serve the same goal:

# Hollow Canticle should feel deliberate, alive, responsive, and polished.

Build **Hollow Canticle v0.7.0 — Living Steel & Foundations** now.
